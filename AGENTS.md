# Markdowntown

Десктопный редактор Markdown-файлов с панелью живого превью отрендеренного текста.
Цель — поддержка основных элементов Markdown (CommonMark + таблицы) и диаграмм Mermaid.

- Язык: Rust (edition 2024, toolchain 1.99+)
- GUI: `egui` / `eframe` 0.36.2 (бэкенд wgpu)
- Целевая платформа: Windows (кроссплатформенность — позже, не ломать без нужды)
- Имя: «Markdowntown» в UI и документации, `markdowntown` — пакет и exe. Прежнее имя —
  mdview: так пока называется папка репозитория и стенды в `experiments/`.

## Команды

```sh
cargo run             # запуск (debug)
cargo build --release # release-сборка (без консольного окна)
cargo clippy          # линтер
cargo fmt             # форматирование
.\check.ps1           # все проверки перед коммитом: fmt, clippy -D warnings, test, build
.\check.ps1 -Release  # + release-сборка и размер exe; -Perf — замеры кадра
.\package.ps1         # check.ps1 + cargo audit + release + проверка DLL + лицензии → dist\*.zip
```

Визуальная проверка: `tools\screenshot.ps1` снимает окно приложения (и может отправить
клики/ввод — только если окно на переднем плане).

`package.ps1` требует `cargo-about` (`cargo install cargo-about --locked --features cli`)
и `cargo-audit` (`cargo install cargo-audit --locked`). Аудит падает только на известных
уязвимостях (база RustSec, нужна сеть; без сети — `-SkipAudit`); предупреждения
«unmaintained» — у транзитивных `bincode`, `yaml-rust` (через `syntect`), `rustybuzz`,
`ttf-parser` (через `resvg`) — уходят с обновлением этих крейтов.
Иконка: исходник `assets/icon.svg`, файлы `icon.ico` / `icon-256.png` генерируются
`cargo test generate_icon_files -- --ignored` и коммитятся.

Выпуск версии X.Y.Z:
1. Версия в `Cargo.toml`, пункт в ROADMAP (фаза 6), описание для пользователей
   `docs/releases/vX.Y.Z.md` (по-английски, как прошлые).
2. `.\package.ps1`; распаковать `dist\Markdowntown-X.Y.Z-windows-x64.zip`, запустить exe.
3. Коммит «Release X.Y.Z: …», тег `git tag -a vX.Y.Z -m "Markdowntown X.Y.Z"`, push ветки и тега.
4. Релиз на GitHub (`gh`, вход — `gh auth login`):
   `gh release create vX.Y.Z dist\Markdowntown-X.Y.Z-windows-x64.zip --title "Markdowntown X.Y.Z" --notes-file docs\releases\vX.Y.Z.md --latest`

Журнал — `data\markdowntown.log` рядом с exe (для `cargo run` — `target\debug\data\`),
перезаписывается при каждом запуске; уровень — `RUST_LOG`.

## Структура

- `build.rs` — ресурсы exe (иконка, сведения о версии) через `winresource` (нужен `rc.exe`
  из Windows SDK).
- `assets/` — иконка, `fonts/Ubuntu-Bold.ttf` (жирный шрифт заголовков превью, вшит);
  `licenses/` — лицензии, которые `cargo-about` не находит сам (шрифты KaTeX внутри
  `ratex-katex-fonts`, Ubuntu Bold — UFL), копируются в архив целиком; `about.toml` / `about.hbs` — допустимые
  лицензии зависимостей и шаблон `THIRD_PARTY_LICENSES.html`.
- `src/main.rs` — точка входа, настройки окна (`NativeOptions`), путь persistence
  (`<каталог данных>pp.ron`), `run_native`.
- `src/data_dir.rs` — каталог данных: `data\` рядом с exe или `%APPDATA%\Markdowntown`.
- `src/settings.rs` — `Settings` (serde, `#[serde(default)]` — старые файлы читаются),
  недавние файлы; сохраняется в `App::save`.
- `src/recovery.rs` — черновики восстановления после сбоя (`data\drafts\*.json`).
- `src/gpu.rs` — выбор графического адаптера: DX12 → Vulkan → OpenGL → WARP, встроенная
  видеокарта раньше дискретной; выбранный адаптер пишется в журнал до создания устройства.
  `WGPU_BACKEND` (`dx12`/`vulkan`/`gl`) ограничивает выбор для диагностики.
- `src/links.rs` — ссылки из превью: `egui_commonmark` открывает их командой `OpenUrl`
  (в браузере); `app.rs` (`handle_links`) забирает локальные из вывода кадра. `classify`:
  Markdown-файл — во вкладке (уже открытый — переключение), `#якорь` и `file.md#якорь` —
  переход к заголовку (`find_anchor`, слаги как в HTML-экспорте), безопасные типы
  (документы, картинки) — программой по умолчанию, прочие файлы — только показать
  в Проводнике (клик по ссылке ничего не запускает), внешние — браузеру.
- `src/logging.rs` — журнал в каталоге данных, запись паник; в `main` — окно с ошибкой,
  если приложение не смогло запуститься.
- `src/fonts.rs` — системные шрифты Windows: запасные для символов, выбор шрифта редактора
  (семейство `editor`), жирный шрифт превью — заголовки и `**жирный**` (семейство `heading`,
  Ubuntu Bold из `assets/fonts`); `install` вызывать при старте и смене шрифта.
- `src/app.rs` — `MarkdowntownApp`: вкладки (всегда хотя бы одна), меню File / View, строка
  вкладок, горячие клавиши, панели и режимы вида, строка статуса. Действия (`Action`: New,
  Open, Close, Exit) идут через `request`: Open открывает файл в новой вкладке (уже открытый —
  переключает на него; пустую безымянную вкладку заменяет), Close и Exit при несохранённых
  правках спрашивают — Exit по очереди про каждую вкладку. Сеанс: пути открытых файлов и
  активная вкладка — в `Settings::session`, при старте открываются снова (нет сеанса —
  приветствие). Также: drag-and-drop, перехват закрытия окна, общий `DiagramService`.
  Файл из первого аргумента командной строки открывается при старте поверх сеанса.
- `src/tab.rs` — `Tab`: документ и его состояние — редактор (свой id текстового поля:
  курсор и отмена), превью, синхронная прокрутка, оглавление, черновик (у безымянной
  вкладки — свой ключ `untitled_key`), проверка файла на диске (активная вкладка — раз
  в секунду, фоновая — при переключении на неё). Элементы egui вкладки — под `push_id(tab.id)`.
- `src/document.rs` — `Document`: текст (всегда с `\n`, без BOM), путь, `dirty`, формат файла
  (BOM, CRLF/LF), `version()` — ключ для кэшей. Чтение/запись с сохранением формата,
  атомарная запись. После правки `text` вызывать `mark_edited()`. `disk_change()` —
  изменён ли файл другой программой; `reload()`, `accept_disk_state()`, `recovered()`.
- `src/segment.rs` — `split()`: документ → сегменты, по одному на блок верхнего уровня
  (Markdown) или ```` ```mermaid ```` верхнего уровня, с байтовыми диапазонами и номерами
  строк. У Markdown-сегмента `appendix` — невидимый хвост с определениями ссылок и сносок
  из других блоков, чтобы поблочный рендер их находил.
- `src/preview.rs` — `Preview`: поблочный рендер — каждый Markdown-блок отдельным вызовом
  `egui_commonmark` (`render_until` скрывает `appendix`); невидимые блоки с подтверждённой
  высотой не рисуются, а занимают место (кэш высот по тексту, ширине и масштабу) — кадр
  на 200 КБ ~2 мс. Mermaid-блоки — через `DiagramService` с debounce. Якоря синхронной
  прокрутки — верх каждого блока. Размер текста — `PREVIEW_BODY_SIZE` (14 pt), код — 0.9
  от него; цвета текста — как у GitHub.
- `src/perf_tests.rs` — замеры кадра без окна (`cargo test --release perf -- --ignored
  --nocapture`) и тест точности пропуска невидимых блоков.
- `src/style.rs` — общий вид: размеры шрифтов интерфейса (`apply_global`, 14 pt вместо 12.5),
  цвет текста для чтения (`reading_text_color`, `apply_reading_colors`), шрифт редактора
  по умолчанию и допустимый диапазон.
- `src/diagram/` — рендер Mermaid:
  - `mod.rs` — трейт `DiagramRenderer`, `DiagramTheme`;
  - `merman_backend.rs` — реализация на `merman` (по `Renderer` на тему; своя палитра для
    тёмной темы — `dark_config()`; лимит 10 с на диаграмму);
  - `raster.rs` — SVG → `egui::ColorImage` через `resvg` (системные шрифты, лимит 8192 px);
  - `service.rs` — `DiagramService`: фоновый поток, кэш текстур по `DiagramKey`. Протокол кадра:
    `begin_frame` → `get`/`peek` для всех нужных диаграмм → `end_frame` (отменяет задания,
    не запрошенные через `get` в этом кадре).
- `src/editor/` — редактор:
  - `mod.rs` — `Editor`: `TextEdit` с подсветкой и номерами строк, панель поиска/замены,
    горячие клавиши (обрабатываются до `TextEdit`), программные правки через `apply_edit`
    (отдельный шаг undo); отдаёт `EditorGeometry` для синхронной прокрутки;
  - `highlight.rs` — Markdown → `LayoutJob` (флаги на байт по событиям `pulldown-cmark`);
  - `commands.rs` — чистые функции правок: обёртка маркерами, ссылка, продолжение списков;
  - `search.rs` — поиск (в т.ч. без учёта регистра для кириллицы) и замена.
- `src/export.rs` — экспорт в HTML: события `pulldown-cmark` → `push_html` с подменой
  блоков кода (`syntect`, классы `hl-*`), mermaid (SVG в `<picture>`, размер из
  `viewBox`), локальных картинок (data URI) и raw HTML (текстом). `PageTheme` — по теме
  приложения: Auto (`prefers-color-scheme`) / Light / Dark; печать светлая. В приложении — в фоновом
  потоке. Примеры для просмотра: `cargo test export_examples -- --ignored` → `target\export\`.
- `src/file_assoc.rs` — ассоциация с `.md` / `.markdown` в HKCU (`winreg`): `register`,
  `unregister`, `status` (в т.ч. «зарегистрирована другая копия»), открытие Параметров →
  Приложения по умолчанию. Только Windows (`#[cfg(windows)]`); тесты пишут в отдельную
  ветку `HKCU\Software\Markdowntown-test-*`, а не в настоящие ассоциации.
- `src/outline.rs` — оглавление: `headings()` (все заголовки, кэш по версии документа),
  `current_index()` — текущий раздел, `Outline::show` — список в левой панели. Переход:
  `Editor::jump_to` (курсор и прокрутка) + прокрутка превью в `tab.rs` (`jump_preview`,
  повтор, пока высоты блоков не устоятся; `ScrollSync::expect_preview`).
- `src/scroll_sync.rs` — `ScrollSync`: ведущая/ведомая панель, сопоставление через байт
  документа в верхней строке; `PreviewGeometry` — якоря превью.
- `src/math.rs` — формулы LaTeX: `render()` — LaTeX → SVG через `ratex` (глифы контурами,
  размеры в единицах SVG, глубина под базовой линией); `MathCache` — текстуры для превью
  (рисуются сразу, без фонового потока; строчные — по базовой линии текста). Формулы
  в 1.21 раза крупнее текста (`MATH_SCALE`, как в KaTeX).
- `src/viewer.rs` — `DiagramViewer`: окно просмотра диаграммы крупно (масштаб вокруг точки,
  прокрутка, перетаскивание, растр повышенной плотности при увеличении).
- `examples/showcase.md` — все поддерживаемые элементы Markdown, `examples/mermaid.md` —
  все проверенные типы диаграмм (`cargo run -- examples/<файл>.md`).

## Зависимости

| Крейт | Назначение |
|-------|------------|
| `eframe`, `egui` | окно и immediate-mode UI |
| `egui_commonmark` | рендер Markdown в egui (на базе `pulldown-cmark`) |
| `rfd` | нативные диалоги открытия/сохранения файлов |
| `pulldown-cmark` | разбор Markdown для сегментации (опции — как в `egui_commonmark`) |
| `egui_extras` | загрузчики картинок; feature `svg_text` — текст внутри SVG |
| `image` | декодеры PNG/JPEG/GIF/WebP/BMP для картинок в превью |
| `merman` | Mermaid → SVG (версия зафиксирована `=0.9.0`) |
| `resvg` | SVG → растр; версия как у `egui_extras` (0.45), чтобы не было дубликата |
| `serde_json` | конфиг темы для `merman` |
| `winreg`, `windows-sys` | ассоциация с `.md`: реестр HKCU и `SHChangeNotify` (только Windows) |
| `ratex-*` | формулы LaTeX → SVG; версия — как у `merman` (`=0.1.14`), иначе дубликат |
| `syntect` | подсветка кода в экспорте HTML (та же версия и features, что у `egui_commonmark`) |

`egui_commonmark` подключён с features `better_syntax_highlighting`, `svg`, `fetch`
(картинки по URL; HTTP через `ureq` + rustls, без OpenSSL).

`egui_commonmark` и `egui_commonmark_backend` подменены пропатченными копиями из `vendor/`
через `[patch.crates-io]`: размеры заголовков H1–H6 как на GitHub, `render_until` для
поблочного рендера, ширина метки сноски, вложенные цитаты, таблицы по ширине панели
(перенос текста в ячейках, разделители столбцов). Подробности и порядок обновления —
[vendor/README.md](vendor/README.md). При обновлении `egui_commonmark` проверять, что патч
применился: `cargo tree -i egui_commonmark` и `cargo tree -i egui_commonmark_backend`
должны показывать пути `vendor/...`.

В `[profile.dev.package."*"]` у зависимостей отключена отладочная информация —
иначе debug-сборка занимает несколько ГБ.

Версия `egui_commonmark` должна быть совместима с версией `egui`. После обновления зависимостей
проверять `cargo tree -i egui` — в дереве должна быть ровно одна версия `egui`.

## Особенности API egui 0.36

Многие примеры в интернете написаны под старые версии. В 0.36:

- `eframe::App` требует `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut eframe::Frame)`
  (вместо старого `update(ctx, ...)`). Логику без отрисовки можно класть в `fn logic(ctx, frame)`.
- `TopBottomPanel` и `SidePanel` заменены на `egui::Panel::{top, bottom, left, right}(id)`;
  ширина/высота задаются через `.default_size(..)`.
- Панели и `CentralPanel` показываются через `.show(ui, ..)`, а не `.show(ctx, ..)`.
- Меню: `egui::MenuBar::new().ui(ui, ..)`.

При сомнениях смотреть исходники в `~/.cargo/registry/src/*/egui-0.36.2/` и `eframe-0.36.2/`.

## Решения

- **Превью — гибрид.** У `egui_commonmark` нет хука для блоков кода (только `render_math_fn`
  и `render_html_fn`), поэтому документ сами режем на сегменты: обычный Markdown рендерит
  `egui_commonmark`, блоки ```` ```mermaid ```` — наш код. Сегменты хранят номера строк
  исходника — на этом строится синхронная прокрутка.
- **Обновление превью:** Markdown — сразу (с кэшем разбора), mermaid — debounce ~500 мс.
- **Редактор — стандартный `TextEdit`**, ориентир — файлы до ~200 КБ.
- **Документ** — структура `Document`; вкладка (`Tab`) — документ и состояние вокруг него.
  Сеанс (открытые файлы) восстанавливается при запуске; безымянные вкладки — нет.
- **Файлы:** только UTF-8; BOM и тип окончаний строк (CRLF/LF) запоминаются при чтении и
  восстанавливаются при записи.
- **Markdown-диалект:** GFM (таблицы, task-lists, зачёркивание, сноски, alerts) и формулы
  `$…$` / `$$…$$` (`Options::ENABLE_MATH` — в общих опциях парсера `segment::parser_options`).
  Raw HTML и front matter не поддерживаем. Картинки по URL загружаем.
- **Внешние изменения файла:** без локальных правок — перечитать молча, с правками — спросить.
- **Защита данных:** черновик для восстановления после сбоя в каталоге данных (см. ниже), файл не трогаем.
- **Поставка — самодостаточная portable-сборка:** «распаковал → запустил → работает» на чистой
  Windows 10/11, без установки чего-либо (Node, VC++ Redistributable, шрифтов и т.д.).
  Следствия:
  - CRT линкуется статически (`+crt-static` в `.cargo/config.toml`);
  - все ресурсы (иконка, шрифты, темы подсветки) вшиваются в exe;
  - сетевой код — только на rustls, без OpenSSL;
  - графика должна запускаться без нормального GPU (VM, RDP): fallback на WARP или `glow`;
  - установщика нет; ассоциация с `.md` — кнопкой в настройках (HKCU, без прав администратора).
- **Размер exe:** до ~100 МБ приемлемо. Приоритет — функционал; минимизация размера —
  желательна, но вторична (не отказываться от возможностей ради мегабайт).
- **Каталог данных** (настройки, недавние файлы, черновики): `data\` рядом с exe; если туда
  нельзя писать — `%APPDATA%\Markdowntown`. Для eframe задавать `NativeOptions::persistence_path`,
  не полагаться на путь по умолчанию.
- **Экспорт:** только HTML.
- **Проверки — локальные**, CI на внешнем хостинге нет.

## Mermaid

Рендер — нативный крейт [`merman`](https://github.com/Latias94/merman) (его же использует Zed),
без Node.js и JS-движков. Обоснование и замеры — [docs/research/mermaid.md](docs/research/mermaid.md).

- Подключать с `default-features = false` и features `all-diagrams` + `complete-svg`
  (все типы диаграмм, cytoscape-раскладка, формулы; +~17.5 МБ к exe — в рамках бюджета).
  **Не включать** `layout-elk` (лицензия EPL-2.0) — то есть не использовать default features.
- SVG получать только через `SvgPipeline::resvg_safe()` — `resvg` не поддерживает
  `<foreignObject>`, без этого пропадут подписи.
- Цепочка: `merman` → SVG → `resvg` → текстура egui. Один `Renderer` (`Send + Sync`) в фоновом
  потоке, кэш по хэшу (исходник + тема + `pixels_per_point`). Пока диаграмма не готова — показывать
  предыдущую версию; ошибки разбора показывать текстом.
- Тема: `Engine::with_site_config` с `{"theme": "dark" | "default"}` по текущей теме egui.
- Рендерер спрятан за трейтом `DiagramRenderer` (запасной вариант — крейт `mermaid-svg`).
- `merman` — версия 0.x: версию фиксировать, обновлять осознанно.
- Стенд для сравнения рендереров — `experiments/mermaid/` (вне основной сборки).

## Принципы

- **Просто и только нужное (KISS, YAGNI).** Делать то, что требуется сейчас; границы
  возможностей — в «Решениях» и в «Не планируется» ROADMAP. Отложенное — пунктом в ROADMAP,
  а не заделом в коде.
- **Без дублирования (DRY) — по смыслу, а не по числу строк.** Перед новым кодом поискать
  готовое (`segment::parser_options`, `export::slugify`, `Rasterizer` и т.п.). Похожий код
  для разных задач, который будет меняться независимо, объединять не нужно.
- **Логика — в чистых функциях с тестами**, UI — тонкий слой над ними (пример: `commands.rs`,
  `search.rs`, `links.rs`). Интерфейс проверять вживую: `tools\screenshot.ps1`, своя копия
  exe с отдельным каталогом данных, чтобы не трогать настройки пользователя.
- **Размер функций — ориентир, а не правило.** Логику длиннее ~50 строк или с глубокой
  вложенностью — дробить. Код раскладки egui (immediate mode) читается сверху вниз
  и может быть длиннее; дробить его, только если части осмысленны сами по себе.
- **Ошибки — `Result` и сообщение пользователю** (строка статуса и журнал), без паник;
  `unwrap`/`expect` — только для инвариантов, которые не зависят от ввода.
- **Производительность — по замерам** (`perf_tests.rs`, `.\check.ps1 -Perf`), а не на глаз;
  оптимизировать то, что видно пользователю.
- **Зависимости — осознанно.** Новый крейт — только с понятной пользой: проверить
  `cargo tree -d` (нет ли второй версии), прирост exe в release и лицензию (`about.toml`).
  Сначала проверить, нет ли нужного уже в дереве (так подключены `ratex`, `syntect`, `winreg`).
  Известные уязвимости — `cargo audit` (входит в `package.ps1`).
- **Безопасность ввода.** Документ — чужие данные: raw HTML не исполняем, клик по ссылке
  не запускает программы, пути из документа не выходят за пределы явного действия пользователя.

## Соглашения

- Во встроенных шрифтах egui нет многих символов (↑ ↓ ▲ ✓ → …) — они рисуются
  квадратиками. Все не-ASCII символы интерфейса перечислены в тесте `UI_SYMBOLS`
  (`src/app.rs`); новый символ — сначала добавить туда и прогнать тесты.
- Тексты UI и сообщения пользователю — на английском, строки прямо в коде
  (локализация не планируется — см. ROADMAP). Документация и комментарии — на русском.
- Ошибки ввода-вывода не паниковать, а показывать в строке статуса.
- Перед коммитом: `.\check.ps1` (fmt, clippy без предупреждений, тесты, сборка).
