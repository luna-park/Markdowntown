# mdview

Десктопный редактор Markdown-файлов с панелью живого превью отрендеренного текста.
Цель — поддержка основных элементов Markdown (CommonMark + таблицы) и диаграмм Mermaid.

- Язык: Rust (edition 2024, toolchain 1.99+)
- GUI: `egui` / `eframe` 0.36.2 (бэкенд wgpu)
- Целевая платформа: Windows (кроссплатформенность — позже, не ломать без нужды)

## Команды

```sh
cargo run             # запуск (debug)
cargo build --release # release-сборка (без консольного окна)
cargo clippy          # линтер
cargo fmt             # форматирование
```

## Структура

- `src/main.rs` — точка входа, настройки окна (`NativeOptions`), `run_native`.
- `src/app.rs` — `MdViewApp`: состояние (текст, путь, флаг `dirty`, кэш рендера), меню «Файл»,
  горячие клавиши (Ctrl+O / Ctrl+S / Ctrl+Shift+S), панель редактора слева, превью справа, строка статуса.

## Зависимости

| Крейт | Назначение |
|-------|------------|
| `eframe`, `egui` | окно и immediate-mode UI |
| `egui_commonmark` | рендер Markdown в egui (на базе `pulldown-cmark`) |
| `rfd` | нативные диалоги открытия/сохранения файлов |

Версия `egui_commonmark` должна быть совместима с версией `egui`. После обновления зависимостей
проверять `cargo tree -i egui` — в дереве должна быть ровно одна версия `egui`.

## Особенности API egui 0.36

Многие примеры в интернете написаны под старые версии. В 0.36:

- `eframe::App` требует `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut eframe::Frame)`
  (вместо старого `update(ctx, ...)`). Логику без отрисовки можно класть в `fn logic(ctx, frame)`.
- `TopBottomPanel` и `SidePanel` заменены на `egui::Panel::{top, bottom, left, right}(id)`;
  ширина/высота задаются через `.default_size(..)`.
- Панели и `CentralPanel` показываются через `.show(ui, ..)`, а не `.show(ctx, ..)`.
- Меню: `egui::MenuBar::new().ui(ui, ..)`.

При сомнениях смотреть исходники в `~/.cargo/registry/src/*/egui-0.36.2/` и `eframe-0.36.2/`.

## Решения

- **Превью — гибрид.** У `egui_commonmark` нет хука для блоков кода (только `render_math_fn`
  и `render_html_fn`), поэтому документ сами режем на сегменты: обычный Markdown рендерит
  `egui_commonmark`, блоки ```` ```mermaid ```` — наш код. Сегменты хранят номера строк
  исходника — на этом строится синхронная прокрутка.
- **Обновление превью:** Markdown — сразу (с кэшем разбора), mermaid — debounce ~500 мс.
- **Редактор — стандартный `TextEdit`**, ориентир — файлы до ~200 КБ.
- **Документ** — структура `Document`; UI пока на один документ, но без глобального состояния,
  чтобы вкладки добавлялись без переписывания.
- **Файлы:** только UTF-8; BOM и тип окончаний строк (CRLF/LF) запоминаются при чтении и
  восстанавливаются при записи.
- **Markdown-диалект:** GFM (таблицы, task-lists, зачёркивание, сноски, alerts).
  Raw HTML и front matter не поддерживаем. Картинки по URL загружаем.
- **Внешние изменения файла:** без локальных правок — перечитать молча, с правками — спросить.
- **Защита данных:** черновик для восстановления после сбоя в каталоге данных (см. ниже), файл не трогаем.
- **Поставка — самодостаточная portable-сборка:** «распаковал → запустил → работает» на чистой
  Windows 10/11, без установки чего-либо (Node, VC++ Redistributable, шрифтов и т.д.).
  Следствия:
  - CRT линкуется статически (`+crt-static` в `.cargo/config.toml`);
  - все ресурсы (иконка, шрифты, темы подсветки) вшиваются в exe;
  - сетевой код — только на rustls, без OpenSSL;
  - графика должна запускаться без нормального GPU (VM, RDP): fallback на WARP или `glow`;
  - установщика нет; ассоциация с `.md` — кнопкой в настройках (HKCU, без прав администратора).
- **Размер exe:** до ~100 МБ приемлемо. Приоритет — функционал; минимизация размера —
  желательна, но вторична (не отказываться от возможностей ради мегабайт).
- **Каталог данных** (настройки, недавние файлы, черновики): `data\` рядом с exe; если туда
  нельзя писать — `%APPDATA%\mdview`. Для eframe задавать `NativeOptions::persistence_path`,
  не полагаться на путь по умолчанию.
- **Экспорт:** только HTML.
- **Проверки — локальные**, CI на внешнем хостинге нет.

## Mermaid

Рендер — нативный крейт [`merman`](https://github.com/Latias94/merman) (его же использует Zed),
без Node.js и JS-движков. Обоснование и замеры — [docs/research/mermaid.md](docs/research/mermaid.md).

- Подключать с `default-features = false` и features `all-diagrams` + `complete-svg`
  (все типы диаграмм, cytoscape-раскладка, формулы; +~17.5 МБ к exe — в рамках бюджета).
  **Не включать** `layout-elk` (лицензия EPL-2.0) — то есть не использовать default features.
- SVG получать только через `SvgPipeline::resvg_safe()` — `resvg` не поддерживает
  `<foreignObject>`, без этого пропадут подписи.
- Цепочка: `merman` → SVG → `resvg` → текстура egui. Один `Renderer` (`Send + Sync`) в фоновом
  потоке, кэш по хэшу (исходник + тема + ширина). Пока диаграмма не готова — показывать
  предыдущую версию; ошибки разбора показывать текстом.
- Тема: `Engine::with_site_config` с `{"theme": "dark" | "default"}` по текущей теме egui.
- Рендерер спрятан за трейтом `DiagramRenderer` (запасной вариант — крейт `mermaid-svg`).
- `merman` — версия 0.x: версию фиксировать, обновлять осознанно.
- Стенд для сравнения рендереров — `experiments/mermaid/` (вне основной сборки).

## Соглашения

- Тексты UI и сообщения пользователю — на английском, строки прямо в коде
  (локализация — в «Позже»). Документация и комментарии — на русском.
- Ошибки ввода-вывода не паниковать, а показывать в строке статуса.
- Перед коммитом: `cargo fmt`, `cargo clippy` без предупреждений, `cargo build`.
