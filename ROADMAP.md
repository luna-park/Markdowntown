# ROADMAP

Глобальный план развития Markdowntown. Отмечайте выполненные пункты `[x]`,
частично выполненные — пометкой _(в работе)_. Принятые архитектурные решения — в
разделе «Решения» в [AGENTS.md](AGENTS.md).

**Версия 1.0 = фазы 0–4 + фаза 5 (качество) + пункты фазы 6, помеченные «1.0».**
**Формат поставки — самодостаточная portable-сборка: распаковал → запустил → работает,
ничего не устанавливая.**

## Фаза 2. Mermaid

Встроенный рендер на нативном крейте `merman`, без Node.js —
см. [docs/research/mermaid.md](docs/research/mermaid.md).

- [x] Исследование: нативные крейты vs JS-движок → выбран `merman` 0.9
- [x] Трейт `DiagramRenderer` + реализация на `merman` (`default-features = false`,
      `all-diagrams` + `complete-svg`, без `layout-elk`); версия зафиксирована `=0.9.0`
- [x] SVG через `SvgPipeline::resvg_safe()` → растеризация `resvg` в текстуру egui
- [x] Кэш текстур по ключу (хэш исходника + тема + `pixels_per_point`); вытеснение
      неиспользуемых > 30 с при > 32 записях. Ширина в ключ не входит: при изменении
      ширины панели картинка масштабируется без перерендера
- [x] Фоновый поток (`merman` + `resvg` со шрифтами), debounce 500 мс после паузы в наборе;
      Markdown при этом обновляется сразу; новый документ — без задержки
- [x] Пока новая версия рендерится — показывать предыдущую картинку (приглушённо)
- [x] Заглушки: «Rendering diagram…», ошибка синтаксиса (текст от `merman` + предыдущая
      картинка или исходник)
- [x] Тема диаграмм следует текущей теме egui (`theme: dark / default` через site config)
- [x] Масштабирование: шире панели — уменьшается по ширине; растр в `pixels_per_point`
      для чёткости на HiDPI
- [x] Проверить типы: flowchart, sequence, class, state, ER, gantt, pie, mindmap, timeline,
      gitGraph, journey — `examples/mermaid.md`
- [x] Шрифт для подписей в `resvg`: системные шрифты Windows (загружаются в фоновом потоке)
- [x] Контраст тёмной темы: своя палитра `themeVariables` поверх mermaid dark —
      `cScale0..11` (mindmap, timeline) и `pie1..12` вместо почти чёрных штатных цветов
- [x] Просмотр диаграммы крупно: клик по диаграмме → окно с масштабом (−/+/100%/Fit,
      Ctrl+колесо вокруг курсора), прокруткой и перетаскиванием; при увеличении — растр
      ×2…×4 для чёткости; Esc закрывает
- [x] Отмена устаревших заданий: у каждого задания токен `RenderControl` (`merman`
      `OperationControl`); задания, не запрошенные в очередном кадре, отменяются, в том числе
      уже начатые; лимит 10 с на диаграмму
- [x] Корневой узел mindmap в тёмной теме: был серым с тёмным текстом — `git0` /
      `gitBranchLabel0` в палитре (синий с белым текстом; тот же цвет у ветки main в gitGraph)

## Фаза 3. Редактор

Ориентир по размеру файла — до ~200 КБ, стандартный `TextEdit`.

- [x] Подсветка синтаксиса Markdown в редакторе (`layouter` для `TextEdit`, кэш по хэшу текста)
- [x] Номера строк (логических; перенесённые строки не нумеруются)
- [x] Синхронная прокрутка редактора и превью: якоря по блокам верхнего уровня

- [x] Быстрые действия форматирования: Ctrl+B жирный, Ctrl+I курсив, Ctrl+E код, Ctrl+K ссылка;
      повторное нажатие снимает обёртку
- [x] Автопродолжение списков по Enter: маркированные, нумерованные (+1), task list, цитаты;
      Enter на пустом пункте завершает список

## Фаза 5. Производительность и качество

- [x] Без лишней работы на кадр: поблочный рендер превью с пропуском невидимых блоков
      (кадр на 200 КБ: 22 → 2.4 мс, при наборе 43 → 11 мс), номера строк сегментов —
      одним проходом; замеры в `src/perf_tests.rs`
- [ ] _(не срочно)_ Ускорить редактор при наборе на больших файлах: ~8.6 мс на 200 КБ, из них
      ~3 мс — наша подсветка (можно делать инкрементально), остальное — раскладка текста
      в `TextEdit`; кадр целиком ~11 мс — в пределах 60 fps
- [x] Модульные тесты: сегментация, BOM/EOL, кэш и отмена mermaid, файловые операции,
      команды редактора, поиск, синхронная прокрутка, настройки, черновики (70 тестов)
- [x] `cargo clippy` без предупреждений (в `check.ps1` — с `-D warnings`)
- [x] Локальный скрипт проверок `check.ps1`: fmt, clippy, test, build (`-Release` — ещё
      release-сборка и размер exe, `-Perf` — замеры кадра)
- [x] Логирование (`log` + `env_logger`) в `data\markdowntown.log`: старт, графический
      адаптер, файловые операции и ошибки, паники; шумные библиотеки — только ошибки;
      `RUST_LOG` переопределяет уровень
- [x] Запуск без полноценного GPU: wgpu пробует Vulkan / DX12 / OpenGL и в последнюю
      очередь программный адаптер WARP («Microsoft Basic Render Driver», виден в журнале);
      `glow` не нужен. Если графика всё же не стартует — окно с ошибкой и путём к журналу
      (у release нет консоли). Проверка на VM/RDP — в фазе 6 вместе с чистой Windows
- [x] Свой выбор адаптера (`src/gpu.rs`): на тестовом ноутбуке (AMD + NVIDIA GTX 1650 Ti,
      драйверы 2020 г.) 1.0.0 молча не запускался — по умолчанию брался Vulkan на дискретной
      NVIDIA. Теперь DX12 и встроенная видеокарта в приоритете; адаптер пишется в журнал
      (проверено пользователем на том ноутбуке, 1.0.1)

## Не планируется

- Raw HTML внутри Markdown, YAML front matter — отображаются как есть
- Экспорт в PDF средствами приложения
- Старые кодировки (CP1251 и т.п.)
- Свой виджет редактора для файлов 1 МБ+
- CI на внешнем хостинге (проверки локальные)
- Установщик (поставка только portable)
- Зависимость релизной сборки от Node.js, `mmdc` или других внешних программ
